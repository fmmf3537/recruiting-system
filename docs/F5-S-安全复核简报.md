# F5-S 猎头推荐通道 · 安全设计复核简报

> 复核人：Kimi（切片流水线审核方）｜日期：2026-09-02
> 依据：PRD 第 7 章（F5）+ 服务端源码实读（app.ts / rate-limit.ts / upload-file.ts / candidate.service.ts）
> 结论先行：**PRD 的安全设计覆盖了主要风险面，可进入切片起草**；但有 2 个新增风险点 PRD 未覆盖（§3 第 6、7 条），4 个取舍点需你拍板（§4）。

## 1. 暴露面界定

F5 新增 2 个**无鉴权**接口（系统首次）：

| 接口 | 用途 | 暴露内容 |
|---|---|---|
| `GET /api/referral/:token` | 链接落地页信息 | 机构名 + 绑定职位名（脱敏，无其他数据） |
| `POST /api/referral/:token` | 提交推荐（表单 + 简历文件） | 写入候选人库 + 上传文件 + 触发简历解析 |

其余 5 个机构/链接管理接口均走既有 `authenticate` + 角色权限（hr/admin），不扩大暴露面。

## 2. 威胁模型与 PRD 已有防护（逐条核对，✅ = PRD 已明确且源码具备条件）

| # | 威胁 | PRD 防护 | 源码核实 |
|---|---|---|---|
| 1 | token 被枚举/猜测，伪造链接提交 | 32 位随机串、伪造/过期/停用统一 410 不回显有效性 | ✅ 可实现（须用 `crypto.randomBytes`，禁止 Math.random） |
| 2 | 公开提交被刷，灌垃圾候选人 | POST 限流 15 分钟 10 次/IP | ✅ `trust proxy=1` 已配置（app.ts:65），限流按真实客户端 IP 聚桶；per-端点限流范式有 `middleware/rate-limit.ts` 可抄 |
| 3 | 上传恶意文件（伪装扩展名/可执行文件） | 复用 `validateAndRenameUpload`（magic bytes + 扩展名白名单 + UUID 重命名 + UploadRecord） | ✅ 函数存在于 `utils/upload-file.ts`，直接复用；下载侧已有鉴权 + UUID 白名单 + nosniff |
| 4 | 通过提交探测人才库（查候选人是否已存在） | 查重结果不回显，疑似重复仅内部标记 | ✅ duplicate-checker 本就有脱敏逻辑 |

## 3. PRD 未覆盖的新增风险点（本简报提出）

| # | 风险 | 分析 | 建议 |
|---|---|---|---|
| 6 | **外部简历触发 LLM 成本** | F2-S 的自动打分钩子在 `createCandidate` 的 candidateJob 创建后触发。猎头绑定职位的推荐会自动投递 AI 打分 → **匿名用户可消耗 LLM 额度**（限流下 10 次/15min/IP，但多 IP 可放大） | 建议：猎头来源候选人**不自动打分**，HR 审核通过后手动触发（改一个 if 判断）。见 §4 取舍点 A |
| 7 | **简历解析器攻击面** | 外部上传的 pdf/docx 直接进 `pdf-parse`/`mammoth` 解析（BullMQ worker）。恶意构造文件可能触发解析器崩溃/资源耗尽 | 缓解：worker 已有 try/catch（解析失败只标记不阻塞）；限流压制频次；依赖保持更新。评估为**可接受的残余风险**，无需本切片额外动作 |
| 8 | 落地页 GET 未限流 | PRD 只给 POST 配了限流；GET 可被刷（虽只读，但泄露机构名/职位名给持 token 者——token 持有人本就是合法猎头，风险低） | 建议：GET 配宽松限流（15 分钟 60 次/IP），一行成本 |
| 9 | token 出现在 URL | token 会留在浏览器历史、Nginx access log、Referer 头 | 接受（PRD B 方案本质如此）；缓解：落地页不放敏感数据、链接可一键停用、Nginx 日志访问受控 |

## 4. 待你拍板的取舍点

### A. 猎头简历是否自动 AI 打分？（对应 §3-6）
- **A1（建议）**：不自动打分。HR 审核通过后再手动触发/或推进阶段时触发。理由：匿名入口不应直接消耗 LLM 额度；且未审核的简历打分无意义
- **A2**：保持自动打分（与 HR 自建候选人行为一致），靠 IP 限流控制成本上限

### B. 公开提交成功后给猎头回显什么？
- **B1（PRD 原案，建议维持）**：只回显「已提交，将由 HR 联系候选人」，不回显候选人编号、不回显是否疑似重复
- B2：额外给一个提交凭据编号（便于猎头对账）——代价是多一个可枚举/可探测的标识

### C. 授权同意的法律文本
- PRD 定的是「☑已获候选人授权同意」勾选项 + `consentNote="猎头机构承诺已获候选人授权"` 自动记录
- 待确认：勾选框旁是否需要一段**正式授权承诺文本**（如「本人承诺已获得候选人对本推荐行为的明确授权，同意贵司依据《个人信息保护法》处理其简历信息」）？建议加，文案可由你或法务定，切片里做成可配置常量

### D. 链接默认有效期
- PRD 允许空 = 长期有效。建议切片把**默认有效期设为 90 天**（可改可清空），降低「发出去的链接永久有效」的失控面——你拍板默认值

## 5. 切片提示词将写死的安全红线（预告）

1. token = `crypto.randomBytes(16).toString('hex')`（32 位 hex，128 位熵）
2. 伪造/过期/停用/机构停用 → 统一 410，响应体不含任何区分性信息
3. POST 独立限流器 15min/10 次/IP + GET 独立限流器 15min/60 次/IP（仿 `rate-limit.ts` 范式）
4. 表单 Zod 严格校验（姓名 2-30 字、电话正则、邮箱可选格式、推荐理由 ≤1000 字、授权勾选必 true）
5. 文件只走 `validateAndRenameUpload`；禁止任何路径拼接用户输入
6. 查重结果绝不回显；提交响应固定文案
7. 候选人创建走 service 层复用（不绕过既有 consentNote/source/OperationLog 逻辑）；OperationLog 记录每次公开提交（userId 记链接创建人，detail 标 `via: 'referral'` + token 后 4 位）
8. 集成测试必须覆盖：无 token 提交、伪造 token、过期链接、停用链接、停用机构、超限流 429、未勾授权 400、查重不回显
9. 迁移只生成 SQL 不 apply（agency + agency_link 两表）
