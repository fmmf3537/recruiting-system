# UI 改造安全 Guard Prompt（v1.0）

> **用途**：跑任何 `UI-*` 切片提示词前，**先粘贴本文件**到 Cursor Composer 作为前置规则。
> **目标**：本轮 UI/UX 优化是**纯表现层改造**，必须做到「功能零回归、数据零影响、随时可回退」。
> **适用范围**：UI-S0 / UI-S1 / UI-S2 / UI-S3 / UI-S4 / UI-S5 及后续所有 UI 切片。
> **与 Migration Guard 的关系**：本轮**不涉及**数据库 schema 变更，因此**不需要** `VIBE_CODING_MIGRATION_GUARD.md`；若某切片意外涉及 schema，立即停止并改用 Migration Guard。

---

## 一、最高优先级红线（违反任意一条立即停止）

### 1. 纯前端，零后端改动
- `server/**`、`e2e/**`、`mobile/**` **一行都不许动**。
- 任何 `package.json` / `pnpm-lock.yaml` / `tsconfig*` / `vite.config*` / `eslint*` / `.env*`，**一个字符都不许改**。
- 不改 `server/prisma/schema.prisma`（不新增字段、不改 enum、不改关联）。
- 越界自检：`git diff --stat -- server e2e mobile` 必须 **0 行**。

### 2. 不改任何 API 契约
- 不新增、不删除、不修改 `client/src/api/*.ts` 里已有函数的**请求参数与响应解析结构**。
- 不新增后端接口调用；只允许调用**现有已存在**的接口。
- 若某个交互效果确实需要新接口 → **停止**，在交付报告里列出「需要的接口」交人类决策，**不要自己造一个假请求或前端 mock**。

### 3. 不删除任何数据绑定（最容易踩的坑）
- 现有 `el-table-column` 的 `prop`、`el-form-item` 的 `prop`、任何 `v-model` 绑定，**只允许**：调整顺序 / 宽度 / 显示样式 / 显隐默认值；**不允许删除绑定关系**。
- 本轮要"去掉"的列，一律改为**默认隐藏但可通过「列设置」重新勾选**（数据仍在，不丢字段）。
- 现有筛选条件、分页参数、排序参数**一个都不能少**。

### 4. 不删除任何功能入口
- 菜单项、按钮、路由：**只做归组与重命名，不做删除**。
- 若某个入口要"弱化"，改为收进下拉/折叠区，**保留可访问路径**。
- 路由 `path` 与 `name` **禁止修改**（外部可能有收藏/书签）。

### 5. 可回退（强制）
- 每个切片引入的布局变更，必须通过**前端开关**控制（统一放在 `client/src/stores/app.ts` 的 UI flag，或 `localStorage` 键 `ui:new-layout:<切片ID>`），开关关闭时**完全回到改造前渲染**。
- 样式改动必须落在**新增的 token / 新增 class** 上，禁止直接覆写 Element Plus 全局组件样式影响未改造页面。
- 交付报告必须写明「回退方式：一行命令 / 一个开关」。

### 6. 禁止整文件重写
- 既有文件一律**最小化增量 diff**，禁止 `rewrite` 整文件。
- 新增文件：UTF-8 无 BOM、LF 行尾、2 空格缩进、单引号、中文注释（Prettier 惯例）。

### 7. 禁止新增依赖
- Element Plus / ECharts / Vue / Pinia 已有，**不装任何新包**（包括图标库、动画库）。

### 7.5 ⚠️ 使用 `$ui-*` 变量必须带 `lang="scss"`（UI-S0 实测踩坑）
- `vite.config.ts` 通过 `preprocessorOptions.scss.additionalData` 全局注入 `@use "@/assets/css/variables.scss" as *;`，**该注入只对 `lang="scss"` 的样式块生效**。
- 因此：**任何用到 `$ui-*` 变量的 `<style>` 块，必须写成 `<style scoped lang="scss">`**。漏写 `lang="scss"` 时：
  - 不会编译报错（CSS 容错静默忽略无效声明），`type-check` / `lint` **都发现不了**；
  - 后果是 `color: $ui-gray-500` 这类声明**整条失效**，样式回退到继承值，只在肉眼看效果时才暴露。
- 交付前自查：`grep -n '\$ui-' <本切片新增/改动的 .vue>` 命中的文件，其 `<style` 标签必须带 `lang="scss"`。

### 8. 不跑验收命令
- `pnpm type-check` / `lint:check` / `test` / `build` **都不跑**，审核方重跑。你只管改对。

## 二、每份切片提示词的固定结构（起草/执行都按这个）

```
⚠️ 强约束（最优先阅读）
1. 任务 ID + 目标
2. 上下文（含「关键已核实事实」：起草人已实读源码，给出精确文件:行号，可直接采信）
3. 必读约束（反直觉点 / 易错点）
4. 实施任务（逐文件，新增文件给完整骨架，既有文件给 before→after 增量 diff）
5. 关键决策点
6. 修改文件清单（必改 / 禁止修改 / 越界检测）
7. 验收标准 + 交付报告模板
```

## 三、验收基线（审核方重跑，禁止新增，也禁止"顺手修存量"）

| 命令 | 基线（INTV-S2 后实测） |
|---|---|
| `client pnpm type-check` | **88** 个存量 TS 错误（不得新增；也不得回退到旧值 90） |
| `client pnpm lint:check` | **137 errors / 224 warnings**（不得新增） |
| `client pnpm test` | 4 文件 / 22 用例全过 |
| `server pnpm test` | 63 文件 / 611 用例全过（本轮不该有任何变化） |
| `git diff --stat -- server e2e mobile` | **0 行** |

> 注意：lint 命令一律用 `lint:check`（无 `--fix` 变体），防止误改源码。

## 四、交付报告必须包含（缺一不可）

1. **完成范围概述**：实际改了哪些文件（含新增）。
2. **文件逐个说明**：新增文件写职责；既有文件**逐处**列 `before → after` 摘要 + 中文注释位置。
3. **功能零回归自检表**（本 Guard 核心，逐项打勾并给证据）：

| 检查项 | 结论 | 证据 |
|---|---|---|
| 现有所有列/字段绑定未删除（仅改顺序/宽度/显隐） | ✅/❌ | 列出改动前后 prop 对照 |
| 现有筛选/分页/排序参数无减少 | ✅/❌ | 列出参数对照 |
| 现有菜单项与路由 path 无删除、无改名 | ✅/❌ | 列出路由对照 |
| 未调用任何新接口，未改 api/*.ts 的既有函数签名 | ✅/❌ | git diff api/ |
| `server/**` `e2e/**` `mobile/**` 改动 0 行 | ✅/❌ | git diff --stat 输出 |
| 无 package.json / lockfile 改动 | ✅/❌ | git status |
| 新布局可通过开关一键回退 | ✅/❌ | 开关名 + 回退步骤 |

4. **交互说明**：改造后交互流程（必要时分角色说明）。
5. **越界自检**：`git status --short` 全文 + `git diff --stat -- server e2e mobile`（必须 0 行）。
6. **已知问题与遗留风险**：如 Element Plus 组件限制、需要后端配合才能完整实现的部分（明确标注「需后端，不在本切片」）。
7. **红线自检确认**：逐条确认第一节 8 条红线。

---

## 五、执行方式

headless 环境无人工确认环节：**先输出实施计划，然后直接动手**，最终回复给出完整交付报告（按第四节 7 项）。

若执行中发现「按提示词做会破坏现有功能或数据」→ **立即停止**，说明冲突点，等人类决策，**不要自行选择折中方案**。
