### 2.2 当前状态（三个已确诊的故障，症状均已实跑复现）

**故障 A：`client` 的 `pnpm type-check` 直接崩溃**
- 命令为 `vue-tsc --noEmit`（`client/package.json` scripts）。
- 崩溃信息：`Search string not found: "/supportedTSExtensions = .*(?=;)/"`，抛自 `vue-tsc@1.8.27` 的 bin。
- 根因：`client/package.json` 声明 `vue-tsc: ^1.8.27`、`typescript: ^5.3.3`，实际解析出 `typescript@5.9.3`；vue-tsc 1.8.x 与 TS ≥5.5 不兼容（volar 1.x 补丁匹配串失效）。
- 修法：将 client 的 devDependency `vue-tsc` 升级到 **2.x 最新稳定版**（先用 `npm view vue-tsc versions --json` 确认 2.x 最新版号，预期在 2.2.x 区间；@vue/language-core 2.x 与 TS 5.9 兼容）。typescript 保持 `^5.3.3` 不动（当前解析 5.9.3 即可）。若 2.x 最新版安装后 `npx vue-tsc --version` 仍报同类错误，允许改用 3.x 最新稳定版并在交付报告中说明。

**故障 B：`client` 的 ESLint 全部文件报 `Resolve error: unable to load resolver "alias"`**
- 现状基线：`pnpm lint` 报 659 errors / 122 warnings，其中约 630+ 条是每个文件 1:1 处的 7 条 `unable to load resolver "alias"`（规则 import/no-duplicates、import/order、import/no-self-import、import/no-relative-packages、import/no-named-as-default、import/no-named-as-default-member 等）。
- 根因：`client/.eslintrc.cjs` 的 `settings['import/resolver']` 使用了 `alias` 这个 resolver 键（对应 npm 包 `eslint-import-resolver-alias`），但 client 的 devDependencies 里**没有安装** `eslint-import-resolver-alias`（仓库里存在的是 `eslint-import-resolver-custom-alias`，键名不同，对不上）。
- 修法：给 client 增加 devDependency `eslint-import-resolver-alias`（用 `npm view eslint-import-resolver-alias version` 确认最新版，预期 1.2.0）。**不改 `.eslintrc.cjs`**。

**故障 C：`server` 的 `pnpm lint` 内存溢出崩溃**
- 命令为 `eslint src --ext .ts --fix`（`server/package.json` scripts，另有 `lint:check` 无 --fix）。
- 崩溃信息：`FATAL ERROR: Ineffective mark-compacts near heap limit Allocation failed - JavaScript heap out of memory`，exit code 134。
- 根因：`server/.eslintrc.cjs` 开了 `parserOptions.project`（类型感知 lint），全量扫描 src 在默认堆下 OOM。
- 修法：把 server 的两个 lint 脚本改为通过 node 直接调 eslint 并加大堆内存（跨平台写法，不引入 cross-env）：
  - `"lint": "node --max-old-space-size=8192 ./node_modules/eslint/bin/eslint.js src --ext .ts --fix"`
  - `"lint:check": "node --max-old-space-size=8192 ./node_modules/eslint/bin/eslint.js src --ext .ts"`
  - 审核方实测：加 8GB 堆后 lint 能跑完（1411 errors / 204 warnings 的存量基线，本次**不需要**修这些错误）。
