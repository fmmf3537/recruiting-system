### 1.2 任务目标
实现 PRD 阶段 5 F4「HR 考核积分」的**周期聚合 + 查询接口层**：

### 2.3 过程质量分 4 维度（PRD §6.3，本切片实现）

| 维度 | 数据来源 | 计算方式（默认） |
|------|---------|-----------------|
| 简历处理时效 | Candidate 创建 → 首次阶段推进的时长 | 48h 内处理率 ≥90% 得满分 10 分，线性递减；**统计周期 = 周** |
| 面试反馈催收响应 | InterviewEvaluation.remindedAt → submittedAt | 催收后 24h 内提交率，满分 10 分 |
| 跟进记录完整度 | CommunicationLog 覆盖率（活跃候选人中有跟进记录的比例） | ≥80% 得满分 10 分 |
| 人才库维护 | 每周至少 N 次有效操作（标签整理/备注更新/查重处理） | 达标 +10 分（默认 N=5，可在规则字典 `description` 字段存数量） |

- 过程分按**周**为最小结算周期（日粒度噪声太大），由 node-cron 每日凌晨增量计算
- 单类失败仅记日志，不影响其他 3 维
- 权重与业务分 7:3（默认，可在 env 配 `HR_SCORE_BUSINESS_WEIGHT` / `HR_SCORE_PROCESS_WEIGHT`）

### 2.4 关键设计决策（PRD §6.6，已拍板）

| 决策点 | 拍板方案 |
|--------|---------|
| 历史数据 | **不回溯**：功能上线日起记分，之前的数据不补 |
| 负分 | Offer 被拒 / 试用期淘汰记负分，默认启用 |
| 多人协作归属 | 记分给动作执行人，不做拆分 |
| 排名可见性 | hr 看名次 + 自己的分，不显示他人具体分数；admin 看全部 |
| 防刷 | 唯一约束幂等；负分约束质量；admin 可撤销异常事件（写 OperationLog） |
| 周期聚合 | **查询时实时聚合**（HrScoreSnapshot 仅存日快照，week/month/quarter/year 由日快照聚合，量小） |

## 3. 必读约束

### 3.1 反直觉点（显式标注）
1. **发射器不改**：F4-S1 业务分发射器 hardcode `category: 'business'`，**不**改它。过程分走独立 service 直接 upsert `hr_score_event.category='process'`，两个 category 同一张表不同值。
2. **快照是日粒度**：week/month/quarter/year 不预先生成，**查询时由 service 实时聚合**（4 周内 day snapshot 求和 = 周分；4 周内求平均 = 月分；以此类推）。HrScoreSnapshot 表**只存日快照**。
3. **过程分来源不是 event**：过程分由 cron 计算后**直接** upsert 到 `hr_score_event` 表（category='process'），不经过发射器。发射器只处理业务分（PR 隔离 + 角色过滤）。
4. **csv 输出 vs xlsx**：服务端不依赖 client/xlsx。**优先 CSV 输出**（`text/csv; charset=utf-8`），简单可靠。`xlsx` 仅在 `server/package.json` 已有 `exceljs` 依赖时使用（先 `cat server/package.json` 检查）。
5. **权限矩阵新增**：
   - `hr-score:read` → HR_PERMISSIONS 追加
   - `hr-score:admin` → HR_PERMISSIONS 已有 `hr_score_rule` 配置（实际行为：admin 用 `*`，hr_score_rule 字典管理页 admin-only 已在 F4-S1 PRD 决策中）

### 3.2 安全与幂等
- 过程分 cron 4 维度任一失败 → 记日志 + continue，**不抛错**阻塞主进程
- 快照 upsert 用 `@@unique([userId, periodType, periodStart])` 天然去重（同日重复跑 = upsert 覆盖）
- admin 撤销异常事件：P2002 仍兜底（事件不会被删除，但 admin 可通过 `/api/hr-score/rules` 调整 `description` 修复后续记分；本期已记分不追溯）
- 排名计算：SQL 窗口函数 `RANK() OVER (PARTITION BY periodType, periodStart ORDER BY totalScore DESC)`，纯查询无副作用

### 4.3 ✱ `server/src/services/hr-score-process.service.ts`（新增，过程分计算）

导出 `async calculateProcessScoresForWeek(weekStart: Date): Promise<{ userId: string; dimension: string; points: number }[]>`：

1. **简历处理时效 (resume_sla)**：查上周的 Candidate，找到 `createdAt < (上周一 + 48h)` 范围；统计 `advanceStage` 首次推进时间 ≤ 48h 的比例 → 线性映射（≥90% 得 10 分，每降 1% 减 1 分，最低 0）
2. **面试反馈催收响应 (interview_response)**：查上周的 InterviewEvaluation where `remindedAt IS NOT NULL`；统计 `submittedAt - remindedAt ≤ 24h` 比例 → 100% 得 10 分，否则按比例（提交率 × 10）
3. **跟进记录完整度 (followup_coverage)**：上周每个 hr 用户的"活跃候选人"（上周内有阶段变化或被操作的候选人）数 vs 其中有 CommunicationLog 的比例 → ≥80% 得 10 分
4. **人才库维护 (talent_ops)**：查上周每个 hr 用户的 `OperationLog`，按 `action` 属于 `{tag_create, tag_update, candidate_update, candidate_duplicate_resolved}` 的 distinct 数 ≥ 5 → 得 10 分，否则按比例

实现要点：
- **每个维度独立 try/catch**，失败仅记 logger.error 返回 null（不影响其他维度）
- 写 `hr_score_event` 时 `category: 'process'`，`bizDate` = 周一日期，`targetType: 'ProcessScore'`，`targetId: 'week:YYYY-MM-DD'`，`remark: '<维度名> 周 YYYY-MM-DD'`
- **同周同一维度同 user 唯一**：依赖 `@@unique([userId, ruleCode, targetType, targetId])` 天然去重（targetId 含周次）

### 4.8 `server/src/lib/cron.ts`（条件修改）

在 `registerInterviewerReminderCron` 之后追加 `registerHrScoreCron()`：

```ts
import { calculateProcessScoresForWeek } from '../services/hr-score-process.service';
import { generateDailySnapshot } from '../services/hr-score-snapshot.service';
import { logger } from '../lib/logger';

export function registerHrScoreCron(): void {
  if (!env.HR_SCORE_CRON) return;
  cron.schedule(env.HR_SCORE_CRON, async () => {
    // 1. 过程分计算（4 维度，单类失败不阻塞）
    try {
      const weekStart = startOfWeek(new Date()); // 周一 00:00
      const result = await calculateProcessScoresForWeek(weekStart);
      logger.info({ count: result.length }, '[过程分] 计算完成');
    } catch (e) {
      logger.error({ err: e }, '[过程分] 计算失败');
    }
    // 2. 日快照（business + process 汇总）
    try {
      await generateDailySnapshot(new Date());
      logger.info('[日快照] 生成完成');
    } catch (e) {
      logger.error({ err: e }, '[日快照] 生成失败');
    }
  });
  logger.info({ expr: env.HR_SCORE_CRON }, '[HR 考核] 已注册');
}
```

在 `src/index.ts` 的 `registerXxxCron()` 序列里追加 `registerHrScoreCron()`。

## 5. 关键决策点

### 5.1 过程分发射不经过现有发射器
F4-S1 的 `emitScoreEvent` hardcode `category: 'business'`。本切片**不改**它，过程分直接由 `hr-score-process.service` 走 `prisma.hrScoreEvent.create`（不调用 `emitScoreEvent`）。两个 category 同一表不同值，写入逻辑独立。

### 5.2 快照是查询时实时聚合
`HrScoreSnapshot` 表**只存日快照**。week/month/quarter/year 由 service 层**查询时**实时聚合日快照（`aggregateFromDailySnapshots`）。rank 字段 SQL 窗口函数计算（同周期内 totalScore 降序 RANK）。

### 5.3 CSV 输出 vs xlsx
服务端**不依赖** client 的 `xlsx` 包。`server/package.json` 检查是否有 `exceljs`，有就用，无则**写 CSV 输出**（`text/csv; charset=utf-8` + BOM 让 Excel 正确识别中文）。

### 5.4 维度 4 的"有效操作"定义
`TALENT_OPS_WEEKLY_DEFAULT=5`，规则字典 `hr_score_talent_ops.description` 字段可覆盖此数（与 `hr_score_rule` 同范式）。`OperationLog.action` 属于 `{tag_create, tag_update, candidate_update, candidate_duplicate_resolved}` 的 distinct 数。

### 5.5 周期对齐
- day：calendar day（今天 00:00 ~ 23:59）
- week：周一 ~ 周日
- month：1 号 ~ 月末
- quarter：1/4/7/10 月首 ~ 季末
- year：1/1 ~ 12/31

查询参数 `period` 用 `week|month|quarter|year|day`，service 内部计算 `periodStart`。
