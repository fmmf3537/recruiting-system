## 1. 任务 ID + 目标

### 1.1 任务 ID
`E2E-P12`

### 1.2 任务目标

1. **e2e API 冒烟**：Offer 完整审批流——创建候选人 → 创建 Offer → 提交审批 → 审批通过 → 标记发送 → 录入答复 → 标记入职
2. **回归哨兵**：保护 `POST /api/offers` + `submit/approve/send/result/join` 全链路不回归

### 1.3 为什么

Offer 审批流是 ATS 最复杂的业务流（draft → pending_approval → approved → sent → accepted → joined），涉及 7 个接口串联。现有集成测试 39 个用例已覆盖后端逻辑，但 e2e API 层无端到端冒烟保护。

### 2.2 后端状态机（`offer.service.ts`）

```
create → draft
submit → pending_approval（需要 approverId，校验审批人存在）
approve → approved（仅 admin 或指定审批人）
reject → rejected（必须填 note）
send → sent（仅 approved）
updateOfferResult → accepted/rejected（仅 approved/sent）
markAsJoined → joined=true（仅 accepted）
```

## 3. 必读约束

### 3.1 反直觉点

1. **offerDate 是 ISO datetime**：用 `new Date().toISOString()`。
2. **submit 需要 approverId**：admin 用户自己的 id 是确定的（`.auth/admin.json` 的 ats_user.id）。
3. **approve 仅 admin 或指定审批人**：admin 直接 approve 通过。
4. **send 仅 approved 状态**：必须在 approve 之后。
5. **result 仅 accepted/rejected**：accepted 后 markAsJoined 才允许。
6. **一个候选人只能有一个 Offer**：重复 create 会 409。测试用唯一 candidate（每次新创建）。

### 3.2 不需要 mock

本 e2e 是真接口测试（不 mock）。需要：
- 后端在跑（PG + Redis + backend）
- `.auth/admin.json` 存在（admin token）
- 候选人真实存在（P3/P10 同模式：测试内创建）

```ts
import { test, expect } from '@playwright/test';
import fs from 'fs';
import path from 'path';

const AUTH_DIR = path.join(__dirname, '..', '..', '.auth');
const ADMIN_AUTH_FILE = path.join(AUTH_DIR, 'admin.json');

// admin 用户的真实 id（从 admin.json 的 ats_user 推导）
const ADMIN_USER_ID = 'cltvlgcmf0000st38ncxpsrhg';

interface StorageState {
  origins: Array<{ origin: string; localStorage: Array<{ name: string; value: string }> }>;
}

function loadAdminToken(): string {
  const raw = fs.readFileSync(ADMIN_AUTH_FILE, 'utf8');
  const state = JSON.parse(raw) as StorageState;
  const entry = state.origins[0]?.localStorage.find((x) => x.name === 'ats_token');
  if (!entry) throw new Error(`admin.json 缺少 ats_token entry`);
  return entry.value;
}

test.describe('Offer 完整审批流 @admin', () => {
  test('创建 Offer → 提交审批 → 审批通过 → 发送 → 答复 accepted → 标记入职', async ({ baseURL }) => {
    const token = loadAdminToken();
    const apiBase = baseURL ?? 'http://localhost:5174';
    const headers = { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` };

    const suffix = Date.now().toString().slice(-8);

    // 1. 创建候选人
    const candRes = await fetch(`${apiBase}/api/candidates`, {
      method: 'POST', headers,
      body: JSON.stringify({
        name: `E2EOffer-${suffix}`,
        phone: `138${suffix.slice(-8).padStart(8, '0')}`.slice(0, 11),
        email: `e2e-offer-${suffix}@test.local`,
      }),
    });
    test.skip(candRes.status !== 201, '候选人创建失败（e2e 环境可能无候选人），跳过');
    const candidate = (await candRes.json()).data;

    try {
      // 2. 创建 Offer
      const offerDate = new Date().toISOString();
      const createRes = await fetch(`${apiBase}/api/offers`, {
        method: 'POST', headers,
        body: JSON.stringify({
          candidateId: candidate.id,
          salary: '25000',
          offerDate,
          expectedJoinDate: new Date(Date.now() + 30 * 86400 * 1000).toISOString(),
          note: 'E2E Offer 测试',
        }),
      });
      expect(createRes.status).toBe(201);
      const offer = (await createRes.json()).data;
      expect(offer.status).toBe('draft');

      // 3. 提交审批
      const submitRes = await fetch(`${apiBase}/api/offers/${candidate.id}/submit`, {
        method: 'POST', headers,
        body: JSON.stringify({ approverId: ADMIN_USER_ID }),
      });
      expect(submitRes.status).toBe(200);
      expect((await submitRes.json()).data.status).toBe('pending_approval');

      // 4. 审批通过
      const approveRes = await fetch(`${apiBase}/api/offers/${candidate.id}/approve`, {
        method: 'POST', headers,
        body: JSON.stringify({ note: 'E2E 审批通过' }),
      });
      expect(approveRes.status).toBe(200);
      expect((await approveRes.json()).data.status).toBe('approved');

      // 5. 标记发送
      const sendRes = await fetch(`${apiBase}/api/offers/${candidate.id}/send`, {
        method: 'POST', headers,
      });
      expect(sendRes.status).toBe(200);
      expect((await sendRes.json()).data.status).toBe('sent');

      // 6. 录入答复 accepted
      const resultRes = await fetch(`${apiBase}/api/offers/${candidate.id}/result`, {
        method: 'PATCH', headers,
        body: JSON.stringify({ result: 'accepted' }),
      });
      expect(resultRes.status).toBe(200);
      expect((await resultRes.json()).data.result).toBe('accepted');

      // 7. 标记入职
      const joinRes = await fetch(`${apiBase}/api/offers/${candidate.id}/join`, {
        method: 'PATCH', headers,
        body: JSON.stringify({ actualJoinDate: new Date(Date.now() + 30 * 86400 * 1000).toISOString() }),
      });
      expect(joinRes.status).toBe(200);
      expect((await joinRes.json()).data.joined).toBe(true);
    } finally {
      // 清理候选人（Offer 随之删除？需确认；软删候选人即可）
      await fetch(`${apiBase}/api/candidates/${candidate.id}`, { method: 'DELETE', headers });
    }
  });

  test('submit 用不存在 approverId → 400', async ({ baseURL }) => {
    const token = loadAdminToken();
    const apiBase = baseURL ?? 'http://localhost:5174';
    const fakeCandId = 'clcand00000000000000001';
    const res = await fetch(`${apiBase}/api/offers/${fakeCandId}/submit`, {
      method: 'POST', headers: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${token}`,
      },
      body: JSON.stringify({ approverId: 'cl' + 'x'.repeat(24) }),
    });
    // schema 校验 cuid 格式，或 service 校验 approver 不存在 → 400
    expect([400, 404]).toContain(res.status);
  });

  test('send 未审批（draft）→ 400', async ({ baseURL }) => {
    const token = loadAdminToken();
    const apiBase = baseURL ?? 'http://localhost:5174';
    const fakeCandId = 'clcand00000000000000001';
    const res = await fetch(`${apiBase}/api/offers/${fakeCandId}/send`, {
      method: 'POST', headers: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${token}`,
      },
    });
    expect(res.status).toBe(404); // 无 Offer + candidateId 不存在 → 404
  });

  test('offerDate 非法值 → 400', async ({ baseURL }) => {
    const token = loadAdminToken();
    const apiBase = baseURL ?? 'http://localhost:5174';
    const fakeCandId = 'clcand00000000000000001';
    const res = await fetch(`${apiBase}/api/offers`, {
      method: 'POST', headers: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${token}`,
      },
      body: JSON.stringify({
        candidateId: fakeCandId,
        salary: '25000',
        offerDate: 'not-a-date',
      }),
    });
    expect(res.status).toBe(400);
  });

  test('salary 为空 → 400', async ({ baseURL }) => {
    const token = loadAdminToken();
    const apiBase = baseURL ?? 'http://localhost:5174';
    const fakeCandId = 'clcand00000000000000001';
    const res = await fetch(`${apiBase}/api/offers`, {
      method: 'POST', headers: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${token}`,
      },
      body: JSON.stringify({
        candidateId: fakeCandId,
        salary: '',
        offerDate: new Date().toISOString(),
      }),
    });
    expect(res.status).toBe(400);
  });
});
```

## 5. 关键决策点

### 5.1 为什么用 admin 当审批人
admin 自己的 id 是确定的（`.auth/admin.json` 的 ats_user.id），且 admin 可以直接 approve。production 应有独立审批人，e2e 简化。

### 5.2 为什么 offerDate 用 now
createOffer schema 要求 `z.string().datetime()`（ISO 格式）。用 `new Date().toISOString()` 保证合法。

### 5.3 为什么候选 2 用 [400,404] 双断言
submit 流程：schema 校验 cuid 格式（400）→ service 校验 approver 存在（400）。若 fake id 恰好 cuid 格式通过，service 会校验 approver 不存在 → 400。用包容断言避免耦合 schema 细节。

### 5.4 不做的
- 不改后端 offer.service.ts（已有 39 集成用例）
- 不改前端 offer.ts
- 不改 prisma schema / migrations
- 不跑验收命令
